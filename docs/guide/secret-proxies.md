# STCP/XTCP 与访问端

普通的 TCP 代理会在 frps 上开放一个公网端口，任何人都能连接。STCP、SUDP、XTCP 代理**不开放公网端口**，只有运行了**访问端（visitor）**并持有相同密钥的机器才能连接，适合 SSH、远程桌面、NAS 管理页这类不想暴露在公网上的服务。

| 类型 | 说明 |
| --- | --- |
| STCP | TCP 流量，经过 frps 中转 |
| SUDP | UDP 流量，经过 frps 中转 |
| XTCP | TCP 流量，先尝试点对点直连（流量不经过 frps），失败时连接不上；适合大流量但对网络环境有要求 |

整个链路需要两端：

```text
被访问的机器（发布代理）                         访问的机器（运行访问端）
Podux / frpc ── STCP 代理 "nas"     ⇄  frps  ⇄   Podux / frpc ── 访问端，监听 127.0.0.1:6000
     └── 本地服务 127.0.0.1:5000                        └── 你连接 127.0.0.1:6000
```

两端连接的必须是**同一个 frps**。两台机器都可以用 Podux 管理，也可以一端用原生 frpc。

## 第一步：发布 STCP/XTCP 代理

在被访问的机器上：

1. **代理** → **添加代理**，类型选择 **STCP**（或 SUDP、XTCP）
2. 填写本地地址和端口，例如 `127.0.0.1:5000`
3. **密钥**：选择类型时会自动生成一个随机密钥，访问端需要填写相同的值
4. **允许的用户**（可选）：留空时只允许同一 frps 用户的访问端连接；填 `*` 允许所有用户，多个用户用逗号分隔
5. 保存

保存后，代理列表的"远程端口 / 域名"一列会显示**访问端填写的名称**，形如 `nas-abc123def456ghi`。Podux 在 frps 上以"名称-ID"注册代理，所以访问端必须用这个完整名称，不能只写 `nas`。

## 第二步：添加访问端

在访问的机器上：

1. **访问端** → **添加访问端**
2. 选择与代理**相同 frps** 的服务器
3. 填写目标代理：
   - 如果目标代理也在这台 Podux 里，用 **从 Podux 中的代理填入** 直接选择，会自动填好服务器、类型、名称和密钥
   - 否则手动填写**代理名称**（第一步复制的名称）和**密钥**；如果目标代理所在 frpc 配置了不同的 `user`，在**代理所属用户**里填写它
4. 填写本机**监听地址**和**监听端口**，例如 `127.0.0.1:6000`。`127.0.0.1` 只允许本机连接，`0.0.0.0` 允许局域网连接
5. 加密和压缩需要与目标代理的设置一致
6. 保存

服务器正在运行时，访问端保存后立即生效。之后连接 `127.0.0.1:6000` 就等于连接被访问机器上的 `127.0.0.1:5000`。

## 用原生 frpc 作为另一端

访问端配置示例（frpc.toml）：

```toml
[[visitors]]
name = "nas-visitor"
type = "stcp"
serverName = "nas-abc123def456ghi"   # Podux 代理列表里复制的名称
secretKey = "与代理相同的密钥"
bindAddr = "127.0.0.1"
bindPort = 6000
```

反过来，原生 frpc 发布的代理名称就是它配置里的 `name`，在 Podux 访问端里直接填写即可。

## 导入

导入 `frpc.toml` 时，STCP/SUDP/XTCP 代理会和其他代理一起导入；`[[visitors]]` 会显示在预览的"访问端"区域，可以选择是否导入、是否覆盖同名访问端。TCPMUX 等仍不支持的代理类型会被跳过并提示。
