# 什么是 Podux?

Podux 是一个**现代化的 frpc 管理平台**，基于 PocketBase 和 React 构建，提供可视化界面来管理内网穿透服务。


## 名称由来

**Podux** = **proxy** + **port** + **dux**（拉丁语：领导者、引导者）

这个名字本身就是一份宣言：不只是一个工具的前端，而是一个统一管理隧道工具的平台。

## 为什么从 frpc-hub 改名？

Podux 的前身是 **frpc-hub**，最初专为管理 frpc 而生。随着项目的成长，目标逐渐清晰 —— 不只是 frp，而是成为支持多种隧道工具的统一管理平台。

**frpc-hub** 这个名字将项目与单一工具绑定，无法承载更大的愿景。**Podux** 代表的是面向未来的设计：一个可以容纳更多隧道协议与工具的统一入口。

> 改名发生于 2026 年 3 月，仓库地址及所有相关引用均已同步更新。

## 背景

[frp](https://github.com/fatedier/frp) 是目前最流行的开源内网穿透工具之一，其客户端 `frpc` 通过配置文件（`.toml` / `.ini`）与服务端 `frps` 建立隧道，将内网服务暴露到公网。

然而，原生 frpc 的使用方式存在一些痛点：

- **纯配置文件驱动**：每次修改都需要手动编辑文件并重启进程
- **多服务器管理困难**：同时维护多个 frps 服务端时，配置容易混乱
- **缺乏可视化监控**：无法直观查看连接状态和延迟情况
- **运维成本高**：升级、备份、迁移全靠手动操作

Podux 正是为解决这些问题而生。

## 核心能力

### 服务器管理

集中管理多个 frps 服务器，支持：

- 每台服务器对应一个独立的 frpc 实例，可单独启动、停止
- token 与 OIDC 认证；tcp、kcp、quic、websocket、wss 传输协议，可配置 TLS 证书
- 开启"自动连接"的服务器在 Podux 启动时自动上线
- 定时探测延迟并保留历史曲线，显示服务器地理位置
- 删除服务器时一并清理其代理和监控数据

### 代理管理

通过可视化表单创建和管理代理隧道，支持以下代理类型：

| 类型 | 说明 |
| --- | --- |
| TCP | 通用 TCP 端口转发 |
| UDP | UDP 流量转发 |
| HTTP | HTTP 反向代理 |
| HTTPS | HTTPS 反向代理 |
| STCP / SUDP | 不开放公网端口，只有持有密钥的访问端才能连接 |
| XTCP | 同上，并尝试点对点直连，流量不经过 frps |
| TCPMUX | 多个 TCP 服务按域名共用 frps 的一个端口 |

每个代理还可以设置加密、压缩、限速、健康检查、HTTP 访问认证与路径分流、负载均衡分组、插件（SOCKS5、静态文件、HTTPS2HTTP 等）和有效期，见[代理进阶设置](/guide/proxy-options)。保存时会检查端口和域名冲突，并在表单中指出冲突的代理；代理列表支持批量启用、停用、迁移和删除。

### 访问端

在本机监听端口，访问其他机器发布的 STCP/SUDP/XTCP 代理，见 [STCP/XTCP 与访问端](/guide/secret-proxies)。

### 告警与导出

- 读取 frps 管理面板显示每个代理的流量，并从外部探测代理是否真的可以访问，见[流量与可达性](/guide/traffic)
- 服务器不可达、延迟过高、代理掉线或外网不可达、frpc 意外退出时，通过 Webhook（含企业微信、钉钉、飞书）、Telegram、Bark 或邮件通知，见[告警通知](/guide/notifications)
- 把服务器的配置导出为原生 frpc 可用的 `frpc.toml`，见[导出配置](/guide/export)
- 在界面中备份、定时备份和恢复全部数据，见[数据与备份](/deploy/backup)

### 热重载

修改代理或访问端后，Podux 会自动触发 frpc 重载，**无需手动重启**。只有配置发生变化的代理会重启，同一服务器上的其他代理不受影响。

### 现代化界面

基于 Radix UI 组件库和 Tailwind CSS 构建，界面简洁美观，支持中英文切换。

## 技术架构

```text
浏览器 (React)  ──HTTP──▶  Podux (PocketBase + 内嵌 frpc)  ──隧道──▶  frps（自行部署）
                                    │
                                    └── pb_data/：SQLite 数据库、frpc 日志与证书
```

- **前端**：React + Radix UI + Tailwind CSS，打包后嵌入可执行文件
- **后端**：[PocketBase](https://pocketbase.io/)，内置 SQLite，负责账号、数据存储和 API
- **frpc**：作为 Go 库内嵌在 Podux 进程中，每台服务器一个实例，不需要单独安装 frpc

Podux 以**单一可执行文件**的形式分发，内嵌了 PocketBase 后端与前端资源，开箱即用，无需额外依赖。

## 与手动管理对比

| 对比项 | 手动管理 frpc | Podux |
| --- | --- | --- |
| 配置方式 | 编辑 `.toml` 文件 | 可视化表单 |
| 重载配置 | 手动重启进程 | 自动热重载 |
| 多服务器 | 维护多份配置文件 | 统一界面管理 |
| 状态监控 | 查看日志 | 实时监控面板 |
| 跨平台部署 | 需配置环境 | 单文件，开箱即用 |

## 适用场景

- **开发者**：快速将本地开发环境（Web 服务、数据库、SSH 等）暴露到公网进行调试或演示
- **运维人员**：统一管理多台机器的内网穿透配置，降低运维复杂度
- **个人用户**：无需记忆复杂的配置语法，通过界面轻松配置家庭服务器、NAS、远程桌面等
