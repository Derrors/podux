# 流量与可达性

## 流量统计

frpc 本身不统计每个代理的流量，Podux 从 **frps 管理面板**（webServer）读取。先在 frps 上开启管理面板：

```toml
# frps.toml
webServer.addr = "0.0.0.0"
webServer.port = 7500
webServer.user = "admin"
webServer.password = "强密码"
```

然后在 Podux 的服务器设置中，填写 **frps 管理面板**的地址（如 `http://frps.example.com:7500`）、用户名和密码，点 **测试连接** 确认。之后可以看到：

- 代理列表和服务器详情页的"外网 / 流量"列：每个代理今日的入站、出站流量和当前连接数，点击查看近 7 天的流量图
- 服务器详情页的"frps 状态"：frps 版本、今日总流量、连接数和在线客户端数
- 仪表盘的"今日流量"：所有已配置面板的服务器之和

流量数据由 frps 保存在内存中，frps 重启后会清零。Podux 每 15 秒最多向每台 frps 查询一次。

::: warning
管理面板的密码保存在 Podux 的数据库中。如果面板开放在公网，请设置强密码，或只允许 Podux 所在的机器访问。
:::

## 外网可达性探测

frpc 显示"在线"只说明隧道已经建立，并不保证从外部真的能访问（例如 frps 所在机器的防火墙没有放行端口，或域名解析不正确）。Podux 以 1 分钟为目标周期，从**自身所在的机器**探测正在运行的服务器上在线的代理：

| 代理类型 | 探测方式 |
| --- | --- |
| TCP | 连接 `服务器地址:远程端口` |
| HTTP | 用代理的域名访问 frps 的 HTTP 端口，带上第一个路径。frps 自己返回的 404 页面（没有匹配的代理）或 502/503/504 视为失败；业务返回的其他状态（包括 401、404）视为可达 |
| HTTPS | 用代理的域名与 frps 的 HTTPS 端口完成 TLS 握手 |

UDP、STCP、SUDP、XTCP、TCPMUX 代理，以及远程端口为 0（由 frps 分配）或只配了通配符域名的代理不会被探测。

TCP、HTTP、HTTPS 代理表单的「网络配置」中提供**外网可达性探测**开关，默认开启（已有代理未设置时也视为开启），可按代理关闭。关闭仅停止 Podux 独立发起的外网探测，不会停用代理、改变穿透配置或影响 frpc 的[本地服务健康检查](/guide/proxy-options#健康检查)。

关闭后，代理列表和服务器详情页的「外网 / 流量」列显示灰色「探测已关闭」，不再显示旧的可达或不可达结果；已配置 frps 管理面板的流量统计、当前连接数和点击查看近 7 天流量历史的功能仍保留。编辑和复制代理会保留开关状态；切换到不支持探测的类型只隐藏开关，不覆盖已保存的值。

HTTP/HTTPS 代理使用 frps 的虚拟主机端口和 `subdomainHost`：配置了管理面板时从 frps 读取，否则按 80、443 处理，子域名代理则跳过。

每轮内各服务器并行探测，分别错峰、限流；同一服务器记录的探测最多 4 个并发，相邻探测的启动间隔至少为 `max(250ms, 1min / N)`（`N` 为该服务器本轮目标数），以分散短连接突发。下一轮须等待所有服务器完成本轮探测，目标较多或响应较慢时会推迟下一轮开始；轮次不重叠，也不追赶补发。这只能缓解突发，不保证消除 FRP 连接池已满错误。

每个探测完成后立即更新可达性结果，显示在"外网 / 流量"列；告警按各服务器的完整轮次判断。开启[告警通知](/guide/notifications)的"代理外网不可达"后，代理连续 3 个完整轮次探测失败会发送通知，恢复后再通知一次。通常约 3 分钟，但取决于完整轮次，目标较多或响应较慢时会更久。

服务停止会取消排队中和进行中的探测，并等待它们退出；取消不记为失败，也不会误报不可达。

::: tip
探测从 Podux 所在的机器发出。如果它和 frps 在同一个内网，或者访问自己的公网地址有限制（部分路由器不支持回环），结果可能与真实的外部访问不同。
:::
