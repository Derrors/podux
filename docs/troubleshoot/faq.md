# 常见问题

## 基础与安装

### Podux 和原生 frpc 有什么区别？

Podux 把 frpc 作为库内嵌在程序里，并提供 Web 界面来管理服务器和代理、查看连接状态与延迟、实时查看日志。不需要手动编辑配置文件，修改后自动生效。

### 支持哪些系统和 frps 版本？

见[兼容性](/guide/compatibility)。

### 数据存在哪里？如何备份？

见[数据与备份](/deploy/backup)。

## 配置与使用

### 现有的 `frpc.toml` 可以直接导入吗？

可以。在 **导入** 页面上传 TOML 文件，预览后选择要导入的代理。地址和端口相同的服务器、以及该服务器下同名的代理会被识别为已存在。注意：

- STCP、SUDP、XTCP 代理和 `[[visitors]]` 访问端都可以导入；TCPMUX 等暂不支持的代理类型会被跳过并提示
- TLS 证书只导入内容，配置中的证书文件路径会被忽略，导入后需要在服务器设置中粘贴证书内容

### 修改配置后怎样生效？

保存代理或访问端后，Podux 会自动热重载对应服务器的 frpc，只有配置发生变化的代理会重启，同一服务器上的其他隧道不受影响。修改服务器本身的连接配置后，需要重启该服务器才会生效。

### 支持哪些代理类型？

支持 **TCP**、**UDP**、**HTTP**、**HTTPS**、**STCP**、**SUDP** 和 **XTCP**，以及 STCP/SUDP/XTCP 的访问端。TCPMUX 暂不支持。见[兼容性](/guide/compatibility)。

### 保存代理时提示端口或域名已被使用

同一服务器上，已启用的 TCP 代理之间、UDP 代理之间不能使用相同的远程端口；HTTP 代理之间、HTTPS 代理之间不能使用相同的子域名或自定义域名。访问端在本机监听，所有服务器的访问端之间也不能占用相同的本地地址和端口。提示里会指出冲突的代理或访问端，修改其中一个，或者先停用另一个即可。

### 如何迁回原生 frpc？

在服务器详情页点击 **导出配置**，下载 `frpc.toml`，见[导出配置](/guide/export)。

## 故障排查

### Docker 部署时，代理连不上本机服务

使用 bridge 网络（`-p 8090:8090`）时，代理"本地地址"里的 `127.0.0.1` 指向的是容器自身。请改用 host 网络，或在代理中填写宿主机的局域网 IP，见 [Docker 安装](/deploy/install/docker#网络模式)。

### Docker 容器启动后反复重启，日志里有 permission denied

挂载的宿主机目录不属于容器用户（UID 1000）。执行 `sudo chown -R 1000:1000 <数据目录>` 后重启容器。

### 服务器无法连接

在服务器详情页打开运行日志，查看 frpc 输出的具体错误。常见原因：地址或端口错误、token 与 frps 不一致、frps 版本过旧（见[兼容性](/guide/compatibility)）、防火墙未放行 frps 端口。

### 如何反馈问题？

请在 [GitHub Issues](https://github.com/Derrors/podux/issues) 提交，并附上 Podux 版本、部署方式、相关日志和复现步骤。日志中的 token 等敏感信息请先打码。
